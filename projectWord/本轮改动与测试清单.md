### 0.1 启动方式变更（重要）

**现在 `start.sh` / `reset-data.sh` 会连前端一起做掉了**，不用再手动起 dev server：

```bash
./start.sh          # 后端打包 + 容器重建 + 前端构建 + 重启 dev server
./reset-data.sh     # 清空数据卷 + 重建 + 前端构建 + 重启 dev server

SKIP_FRONTEND=1 ./start.sh        # 只做后端
FRONTEND_PORT=5180 ./start.sh     # 换前端端口（默认 5173）
```

新增脚本 `frontend-up.sh`：`npm install`（首次）→ `npm run build` → 杀掉占用端口的旧 dev server → 起新的 → 等端口就绪（最多 15 秒）。日志在 `log/frontend-dev.log`。

> 注意：脚本会重启 dev server，但**浏览器里已经打开的页面不会自动刷新**，跑完还是要刷一次页面（样式改动建议 `⌘ + Shift + R`，普通刷新可能命中旧 CSS）。

### 0.2 第二轮修掉的 Bug（都是真 bug，不是样式问题）

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | 私信发送后消息窗口不显示 | `myId` 只读 `localStorage.userId`，它和当前登录 token 不一致时，算出的收件人变成**自己** → 后端拒绝「不能给自己发消息」 | `myId` 改为以 **token 的 sub** 为准；不知道"我是谁"时直接提示，不瞎猜 |
| 2 | 点着点着被踢回登录页 | 请求拦截器在**刷新进行中**时，并发请求会裸发无 token 的请求 → 网关判 401001 → 清登录态 | 并发时挂起等待刷新结果（复用 pendingQueue），刷新成功统一带新 token |
| 3 | 我的发布只显示 4~5 条、底部直接「已经到底啦」 | **`getMyInspires()` 封装没接收 page/size**，一直只拿到后端默认的 5 条 | 给 `getMyInspires` / `getMyCollects` 补上 page/size 参数 |
| 4 | 收藏夹 6 个条数全是 116、点一个所有卡片都变选中、移动弹窗全选 | 收藏夹 ID 是雪花 ID 但以**数字**下发，JS 精度丢失 → 6 个 ID 变成同一个数 | 后端 `CollectFolder` 的 id/userId 加 `@JsonSerialize(ToStringSerializer)`，以字符串下发 |
| 5 | `p-folder` 和 `p-folder-add` 高度不一致 | `.folder.add` 里 `min-height` 写了**两遍**（66px/96px），后者生效 + 默认 content-box | 统一由 `.folder` 的 `height:68px + box-sizing:border-box` 决定 |
| 6 | 新建收藏夹弹窗输入框右侧超出 | 输入框 `width:100% + padding` 但 `box-sizing` 是 content-box | 给 `.tin` 加 `box-sizing:border-box`；并加**全局 reset** `*,*::before,*::after{box-sizing:border-box}` |
| 7 | 收藏夹页有两个「未分类」 | 数据里本来就有名为「未分类」的文件夹，和页面固定卡片重复 | 过滤重名文件夹，顶部那张改成**打开真实的未分类文件夹**（数据不丢） |
| 8 | 详情页海报封面图不显示 | 站外图源（picsum）的 CORS 头在不同网络下不稳定 | 新增本站图片代理 `/api/file/poster-cover`（白名单图源），前端优先走代理 |
| 9 | 后台「分类加子类」失败 | 分类 ID 雪花精度丢失，提交的 parentId 被舍入 | 后台分类/词云实体 id、parentId 以字符串下发 |
| 10 | Cloudflare 上视频拖不动进度 | `FileServeController` 不支持 Range | 改为返回 206 + Content-Range |
| 11 | 重置后库里什么都没有 | 种子第一步要读 admin 密码，空库没有 admin 就整体跳过 | 没有 admin 就**自动创建**（默认 admin/112233） |
| 12 | 演示图依赖 picsum 外链 | 种子图是外链，且 MinIO 从没被用过 | 种子改为**本地生成 60 张图存进 MinIO**，本站接口 `/api/file/view?key=...&w=` 输出，支持缩略图 |

| 私信时间 | 气泡时间早 8 小时 | MySQL 容器时区 UTC + 建表默认值写库 |
| 跳过按钮 | 点了跳过但不显示下一张 | `nextCard()` 未重置 `offsetX`，新卡片带着上一张的位移渲染到屏幕外 |
| 游客点分享 | 被弹回登录页 | `handleShare` 先调需登录的分享计数接口，401 触发全局跳登录 |

| `ResourceRegion` | 206 响应体是 JSON 错误 | 项目未注册 `ResourceRegionHttpMessageConverter`，改为直接返回字节区间 |
| 后台登录 | 一直 401「未携带登录令牌」 | `/api/admin/login` 不在网关白名单；且 `application-dev.yml` 的白名单会覆盖基础配置 |
| 后台接口 | 登录成功后所有 `/api/admin/**` 仍 401 | 前端 request 拦截器只挂前台 token，未挂 `adminToken` |
| 分类中文 | 分类名显示乱码 | 首次灌种子数据用的 mysql 客户端不是 utf8mb4（已在 `init.sql` 加 `SET NAMES utf8mb4`） |
| 首页分类 | 分类是写死的 | 已改为读取 `/api/inspire/public/categories` |

## 七、已知限制

1. **视频上限 50MB**，超出会直接提示失败；需要放宽改 `FileController` 的 `MAX_VIDEO_SIZE`。
2. **视频处理后的中间文件**：不勾「只保留最终版」时原片会一直留在 `data/uploads`，长期会占磁盘；目前没有自动清理。
3. **ffmpeg 来自静态镜像**：`mwader/static-ffmpeg:7.1`，通过多阶段 COPY 进运行镜像。apt 源在当前网络代理下会 502，所以没有走 `apt-get install ffmpeg`。
4. **分类的「X条灵感」**按灵感的 `tag` 字段与分类名匹配统计，标签名和分类名不一致时数量为 0。
5. **分享海报为前端生成**，如果主图来自不允许跨域的图源，图片会退化为渐变底色（picsum、本站 `/uploads` 都已验证可正常绘制）。
6. **后台分类页未做拖拽排序**，排序值靠手填数字。

## 八、快速自查命令

```bash
# 服务状态
docker compose ps

# 分类 / 词云公开接口
curl -s http://127.0.0.1:8080/api/inspire/public/categories | head -c 300
curl -s http://127.0.0.1:8080/api/inspire/public/word-cloud | head -c 200

# 后台登录（应返回 token）
curl -s -X POST http://127.0.0.1:8080/api/admin/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"112233"}' | head -c 200

# 视频 Range 支持（应返回 206 + Content-Range）
curl -s -o /dev/null -D - -H "Range: bytes=0-99" \
  http://127.0.0.1:8083/uploads/<某个mp4文件名>

# 上传目录
ls -l data/uploads | head
```
