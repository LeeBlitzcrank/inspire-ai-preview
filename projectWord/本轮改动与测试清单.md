## 四、本轮修复的 Bug（避免误判为回归）

| Bug | 现象 | 原因 |
| --- | --- | --- |
| 私信时间 | 气泡时间早 8 小时 | MySQL 容器时区 UTC + 建表默认值写库 |
| 跳过按钮 | 点了跳过但不显示下一张 | `nextCard()` 未重置 `offsetX`，新卡片带着上一张的位移渲染到屏幕外 |
| 游客点分享 | 被弹回登录页 | `handleShare` 先调需登录的分享计数接口，401 触发全局跳登录 |
| 视频拖动进度 | Safari 无法播放/拖动 | `FileServeController` 不支持 Range 请求 |
| `ResourceRegion` | 206 响应体是 JSON 错误 | 项目未注册 `ResourceRegionHttpMessageConverter`，改为直接返回字节区间 |
| 后台登录 | 一直 401「未携带登录令牌」 | `/api/admin/login` 不在网关白名单；且 `application-dev.yml` 的白名单会覆盖基础配置 |
| 后台接口 | 登录成功后所有 `/api/admin/**` 仍 401 | 前端 request 拦截器只挂前台 token，未挂 `adminToken` |
| 分类中文 | 分类名显示乱码 | 首次灌种子数据用的 mysql 客户端不是 utf8mb4（已在 `init.sql` 加 `SET NAMES utf8mb4`） |
| 首页分类 | 分类是写死的 | 已改为读取 `/api/inspire/public/categories` |

## 七、已知限制

1. **视频上限 50MB**，超出会直接提示失败；需要放宽改 `FileController` 的 `MAX_VIDEO_SIZE`。
2. **视频处理后的中间文件**：不勾「只保留最终版」时原片会一直留在 `data/uploads`，长期会占磁盘；目前没有自动清理。
3. **ffmpeg 来自静态镜像**：`mwader/static-ffmpeg:7.1`，通过多阶段 COPY 进运行镜像。apt 源在当前网络代理下会 502，所以没有走 `apt-get install ffmpeg`。
4. **分类的「X条灵感」**按灵感的 `tag` 字段与分类名匹配统计，标签名和分类名不一致时数量为 0。
5. **分享海报为前端生成**，如果主图来自不允许跨域的图源，图片会退化为渐变底色（picsum、本站 `/uploads` 都已验证可正常绘制）。
6. **后台分类页未做拖拽排序**，排序值靠手填数字。
