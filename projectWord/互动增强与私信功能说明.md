## 二、引用再创作

### 用户操作

1. 打开任意灵感详情。
2. 点击底部引用按钮。
3. 进入创作页，页面顶部显示被引用的原灵感。
4. 用户编写自己的版本后发布。
5. 新灵感详情显示“引用自某用户”，点击可回到原灵感。

如果引用的目标本身也是引用作品，可以继续点击进入下一层原灵感，形成引用链。

### 数据字段

```text
inspire_main.quote_inspire_id
```

### 接口

创建灵感时提交：

```json
{
  "title": "标题",
  "content": "正文",
  "tag": "生活",
  "quoteInspireId": "100000000000101000"
}
```

详情接口会额外返回：

```text
quoteInspireId
quoteTitle
quoteImg
quoteUserId
quoteNickname
```

引用发布后，原作者会收到 `quote` 类型通知。

## 三、@提及 + 通知

评论正文中写入：

```text
@清爽奶茶 这个思路很好
```

后端会解析 `@昵称`，匹配有效用户后创建 `mention` 通知。登录账号 `user001` 只用于登录，不作为展示侧 @ 名称。

前端在评论框或回复框输入 `@` 时，会读取当前用户已关注的人并展示候选列表，点击后自动补全 `@昵称`。

规则：

- 不能给自己发通知。
- 一条评论中多个 @ 用户会分别通知。
- 通知目标会跳转到对应灵感详情。

## 四、私信增强

### 消息类型

```text
text       普通文字
image      图片
inspire    灵感卡片
```

消息表新增：

```text
type
extra_json
is_read
recalled_at
deleted_by_sender
deleted_by_receiver
update_time
```

### 用户操作

聊天页底部：

- `🖼`：选择并发送图片。
- `🔖`：打开我的发布列表，选择灵感卡片发送。
- 自己的消息下方显示 `已读` 或 `未读`。
- 自己的消息可点击“撤回”。

### 删除会话修复

`conversation_member` 新增：

```text
deleted
last_deleted_at
```

删除会话时只隐藏当前用户这一侧，不删除对方的数据。

当双方重新开始聊天或发送新消息时，成员删除标记会自动复位，因此不会持续出现已经删除的旧提示。

### 账号隐私规则

登录账号 `username` 只用于登录认证，不再出现在非管理页面和公开接口中：

- 灵感、评论、关注列表、私信会话不返回 `username`。
- 用户展示统一使用 `nickname`。
- 公开用户资料只返回昵称、头像、城市和注册时间。
- `@` 提及、提及候选和通知都按昵称处理。
- 后台管理页面仍保留账号字段，便于管理员排查。

### 接口

```text
POST   /api/message/send
POST   /api/message/{id}/recall
POST   /api/message/read
DELETE /api/message/conversation/{id}
```

发送图片：

```json
{
  "toUserId": "100000000000000002",
  "content": "https://img.20sherry.com/upload/demo/1_w800.webp",
  "type": "image",
  "extraJson": "{\"width\":800,\"height\":600}"
}
```

发送灵感卡片：

```json
{
  "toUserId": "100000000000000002",
  "content": "灵感标题",
  "type": "inspire",
  "extraJson": "{\"id\":\"100000000000100001\",\"title\":\"灵感标题\",\"img\":\"/uploads/demo.webp\",\"tag\":\"生活\"}"
}
```

## 五、特别关注

关注列表新增“特别”按钮。

接口：

```text
PUT /api/inspire/follow/{userId}/special
```

请求：

```json
{
  "special": true
}
```

特别关注对象发布新作品后，关注者会收到 `special_publish` 通知。
