# 生产性能优化操作清单

> 目标：解决 `ai.20sherry.com` 首屏慢、图片慢、公开接口每次回源的问题。
> 标注「你操作」的步骤需要在 Cloudflare / 服务器后台完成；标注「我操作」的部分可以直接改项目代码。

---

## 一、Cloudflare 控制台（你操作）

进入：

`Cloudflare Dashboard -> 选择 20sherry.com -> Caching -> Cache Rules`

逐条新建规则。建议按下面的顺序创建。

### 0. 按新版“可视化条件构建器”填写

如果你的页面和截图一致，看到的是：

- `URI 完整`
- `通配符`
- `值`
- `And / Or`

就不要填高级表达式，直接按下面这张表建立独立规则。每行建一条规则即可，最简单的填法是：

| 规则 | URI 完整的值 | 边缘 TTL | 浏览器 TTL |
| --- | --- | --- | --- |
| 静态资源 | `https://ai.20sherry.com/assets/*` | 一年 | 一年 |
| 图片接口 | `https://ai.20sherry.com/api/file/view*` | 一个月 | 一个月 |
| 分类接口 | `https://ai.20sherry.com/api/inspire/public/categories*` | 十分钟 | 一分钟 |
| 词云接口 | `https://ai.20sherry.com/api/inspire/public/word-cloud*` | 十分钟 | 一分钟 |
| 推荐接口 | `https://ai.20sherry.com/api/inspire/public/recommend*` | 一分钟 | 一分钟 |
| 首页 HTML | `https://ai.20sherry.com/` | 五分钟 | 遵循源站 |
| index.html | `https://ai.20sherry.com/index.html` | 五分钟 | 遵循源站 |

操作步骤：

1. 规则名称：填表格第一列对应的名字
2. 选择：`自定义筛选表达式`
3. 字段：选择 `URI 完整`
4. 运算符：选择 `通配符`
5. 值：填表格第二列
6. 匹配时动作中设置：
   - 缓存资格：`符合缓存资格 / Eligible for cache`
   - 边缘 TTL：选择表格第三列
   - 浏览器 TTL：选择表格第四列
7. 保存后，再新建下一条规则

> 如果当前页面没有显示“缓存资格 / 边缘 TTL / 浏览器 TTL”，先输入值并点击“编辑表达式”或继续向下滚动，动作设置通常会在条件区域下面。

> 项目使用 Hash 路由，`/#/login`、`/#/personal` 等页面在 HTTP 层仍然请求 `/`，不需要逐个配置页面规则。

**图片规则的缓存键**

图片规则如果打开截图中的 `缓存密钥 / Cache Key` 弹窗：

- 缓存欺骗盔甲：保持关闭
- 按设备类型缓存：保持关闭
- 忽略查询字符串：保持关闭
- 对查询字符串排序：可选，保持关闭即可
- 查询字符串：选择 `所有查询字符串参数`
- 标头：留空，不要添加

也就是使用 Cloudflare 默认缓存键：

`域名 + 路径 + 全部 Query String`

这样 `key=4.jpg&w=400` 和 `key=4.jpg&w=800` 会各自缓存，不会串图。

> 这一项不是必须的。Cloudflare 默认缓存键已经包含完整 Query String，`key` 和 `w` 会自动参与缓存区分。如果当前套餐没有自定义缓存键，保持 `标准 / 默认` 即可，不影响图片缓存生效。

> 如果打开该弹窗后提示需要升级套餐，直接关闭弹窗、不修改即可。不要选择“忽略查询字符串”，否则不同 `key` 或 `w` 的图片可能互相覆盖。对于当前套餐，Cloudflare 的默认行为已经正确。

### 1. 哈希静态资源缓存一年

**规则名**

`ai-static-assets-immutable`

**匹配条件**

```txt
http.host eq "ai.20sherry.com" and starts_with(http.request.uri.path, "/assets/")
```

**设置**

- Cache Eligibility：`Eligible for cache`
- Edge TTL：`Override origin`，选择 `1 year`
- Browser TTL：`Override origin`，选择 `1 year`

作用：

- 当前主 JS/CSS 只缓存 4 小时
- Vite 文件名带 hash，内容变化会换文件名，可以放心缓存一年

### 2. 图片接口缓存 30 天

**规则名**

`ai-public-images-cache`

**匹配条件**

```txt
http.host eq "ai.20sherry.com" and starts_with(http.request.uri.path, "/api/file/view")
```

**设置**

- Cache Eligibility：`Eligible for cache`
- Edge TTL：`Override origin`，选择 `30 days`
- Browser TTL：`Override origin`，选择 `30 days`
- Cache Key -> Query String：`Include specific parameters`
- 参数填：`key,w`

作用：

- 实测图片当前是 `cf-cache-status: DYNAMIC`
- 24KB 图片也会回源，TTFB 约 1.5 秒
- 图片 key 不变时内容不变，适合长期缓存

> 注意：调整图片后如果要用同一个 key 覆盖，必须在 Cloudflare 手动 Purge Cache。

### 3. 公开接口短缓存

**规则名**

`ai-public-api-short-cache`

**匹配条件**

```txt
http.host eq "ai.20sherry.com" and (
  http.request.uri.path eq "/api/inspire/public/categories" or
  http.request.uri.path eq "/api/inspire/public/word-cloud" or
  http.request.uri.path eq "/api/inspire/public/recommend"
)
```

**设置**

- Cache Eligibility：`Eligible for cache`
- Edge TTL：分类/词云 `10 minutes`，推荐 `1 minute`
- Browser TTL：`Override origin`，`1 minute`

作用：

- 分类接口实测 TTFB 约 2 秒
- 推荐接口实测总耗时约 2.6 秒
- 这些数据没有用户私有信息，短缓存不会影响登录态

如需把三个接口设置成不同 TTL，就拆成三条规则。

### 4. HTML 首页短缓存

**规则名**

`ai-html-short-cache`

**匹配条件**

```txt
http.host eq "ai.20sherry.com" and (
  http.request.uri.path eq "/" or
  http.request.uri.path eq "/index.html"
)
```

**设置**

- Cache Eligibility：`Eligible for cache`
- Edge TTL：`5 minutes`
- Browser TTL：`Respect origin`

作用：

- 当前 HTML 是 `cf-cache-status: DYNAMIC`
- 每次打开首页都会回源，TTFB 约 1 秒

### 5. 开启 Brotli

进入：

`Speed -> Settings -> 协议优化 / Protocol Optimization`

打开：

- `Brotli`

当前实测：

- 主 JS 使用 Gzip，压缩后 76KB
- 开启 Brotli 后通常还能减少约 10%–20%

### 6. 发布前清理 Cloudflare Cache

每次前端部署完成后：

`Caching -> Configuration -> Purge Cache`

至少清理：

- `/assets/*`
- `/`
- `/index.html`

## 二、图片域名检查（你先执行）

项目里已经存在 `img.20sherry.com`，Nginx 配置也已经有：

- `Cache-Control: public, max-age=31536000, immutable`
- `?w=` 缩略图
- 30 天 Nginx 图片缓存

但当前生产演示数据仍然写的是站点代理地址：

```txt
/api/file/view?key=upload/demo/4.jpg
```

所以图片没走已有 CDN。

先在服务器或本机终端测试：

```bash
curl -I 'https://img.20sherry.com/upload/demo/4.jpg?w=400'
```

你要把结果给我：

- 如果返回 `HTTP/2 200`：我可以把公开演示图片切到 `img.20sherry.com`
- 如果返回 `502/403/404`：先修 Cloudflare Tunnel 或 Nginx，否则切过去会整站图片挂掉

### 当前实测结果：502 / 403

本机实测发现三个配置问题：

1. `~/.cloudflared/config.yml` 里 `img.20sherry.com` 指向 `http://localhost:80`，但 `nginx-image` 实际映射端口是 `8088`
2. `docker/minio/nginx/nginx.conf` 把 `/upload/demo/4.jpg` 重写成了 `/inspire-img/demo/4.jpg`，少了 `upload/` 前缀，MinIO 实际对象 key 是 `upload/demo/4.jpg`
3. MinIO 的 `inspire-img` 桶是 `private`，匿名访问返回 403

需要先做：

```bash
# 1. 修改 ~/.cloudflared/config.yml
# img.20sherry.com 的 service 改为：
service: http://localhost:8088

# 2. 重启图片代理
docker compose up -d --force-recreate nginx-image

# 3. 启动 cloudflared 隧道（保持终端常驻）
cloudflared tunnel --config ~/.cloudflared/config.yml run

# 4. 应用 MinIO 桶策略：公开 upload/*，保持 upload/private/* 私有
bash docker/minio/init-public-policy.sh
```

验证：

```bash
curl -I 'http://127.0.0.1:8088/upload/demo/4.jpg?w=400'
curl -I 'https://img.20sherry.com/upload/demo/4.jpg?w=400'
```

两条都应返回 `200`。

`start.sh` 和 `reset-data.sh` 已接入 `docker/minio/init-public-policy.sh`，后续重建容器或清库后会重新应用该策略。

### 1. Google 字体不再全局阻塞

当前所有页面都会加载：

```html
https://fonts.googleapis.com/css2?family=Ma+Shan+Zheng&display=swap
```

但它实际上只有灵感录入页的词云需要。

我会改成：

- 从全局 `index.html` 移除字体 stylesheet
- 只在进入创建灵感页时异步加载
- 或直接自托管字体文件

收益：

- 避免国内网络下 Google Fonts 慢或超时拖住首屏
- 首页、个人页、搜索页不再请求 Google

### 2. 公开接口增加 Redis 缓存

可以给这些接口增加服务端缓存：

- `/api/inspire/public/categories`
- `/api/inspire/public/word-cloud`
- `/api/inspire/public/recommend`

建议 TTL：

- 分类、词云：10 分钟
- 推荐：30–60 秒

收益：

- 不依赖 Cloudflare 也能减少数据库查询
- 后台修改分类/词云后主动清缓存

### 3. 演示图片切到 CDN

前提：第二节的 `curl` 返回 200。

我会修改：

- `DemoDataSeeder` 里的演示图 URL
- 前端图片工具对 CDN 图片统一追加 `?w=400`
- 列表卡片优先使用缩略图和 WebP

收益：

- 图片不再经 Cloudflare → Gateway → Core → MinIO
- 首张图不再需要约 2.5 秒

### 4. 前端首包继续拆分

可做：

- 首页组件继续按需加载
- 把 Element Plus 的大组件从首页依赖里拆出去
- 进一步减少首页主包和 vendor 包

收益不是第一优先级，前三项做完后再处理。

## 四、不要做的缓存配置

不要缓存以下路径：

- `/api/auth/**`
- `/api/message/**`
- `/api/admin/**`
- 带用户 token、私信、个人资料的接口

否则可能出现串号或登录态错误。

## 五、优化后的验收命令

### 检查静态资源缓存

```bash
curl -I 'https://ai.20sherry.com/assets/index-D2I-jkdd.js' \
  -H 'Accept-Encoding: br, gzip'
```

期望看到：

- `cf-cache-status: HIT`
- `content-encoding: br`
- `cache-control` 为一年

### 检查图片缓存

```bash
curl -I 'https://ai.20sherry.com/api/file/view?key=upload/demo/4.jpg&w=400'
```

期望看到：

- `cf-cache-status: HIT`
- `cache-control: public, max-age=2592000`

### 检查公开接口

```bash
curl -I 'https://ai.20sherry.com/api/inspire/public/categories'
curl -I 'https://ai.20sherry.com/api/inspire/public/recommend?page=1&size=10'
```

期望：

- 第一次 `MISS`
- 短时间内第二次 `HIT`

### 如果仍然不是 HIT

实测如果看到：

- `/assets/*`：`cf-cache-status: REVALIDATED`，且 `cache-control` 仍是 `max-age=14400`
- `/api/file/view*`：`cf-cache-status: DYNAMIC`
- 公开接口：`cf-cache-status: DYNAMIC`

说明规则只有匹配条件，没有真正执行缓存动作。逐项检查：

1. 规则是否已启用
2. 规则是否建在 `20sherry.com` 这个 Zone
3. 动作里的 `缓存资格` 是否设置为 `符合缓存资格 / Eligible for cache`
4. `边缘 TTL` 是否选择 `覆盖源站 / Override origin`
5. `浏览器 TTL` 是否也选择了覆盖值
6. 规则列表中是否有更靠前的“绕过缓存”规则
7. 修改规则后执行一次 `Purge Cache`
