## 二、逐项说明

### 1. Element Plus 按需引入

**改动**

- 新增依赖：`unplugin-vue-components`、`unplugin-auto-import`
- `vite.config.js` **重命名为 `vite.config.mjs`**（这两个插件是 ESM-only，CJS 配置加载会报错）
- `vite.config.mjs` 中加入 `AutoImport` + `Components`，并使用 `ElementPlusResolver`
- `main.js` 移除 `import ElementPlus from 'element-plus'`、`import 'element-plus/dist/index.css'` 与 `app.use(ElementPlus)`
- **移除 `manualChunks` 里的 `'element-plus': ['element-plus']`**（保留它会强制整包进同一个 chunk，按需引入就白做了）

**注意点（改这块前必看）**

模板里的 `el-xxx` 会由 resolver 自动按需引入并带上样式；但**用代码调用的命令式组件不会自动带样式**，目前项目里用到的是 `ElMessage`、`ElMessageBox`、以及 `v-loading`，已在 `main.js` 手工补上：

```js
import 'element-plus/es/components/message/style/css'
import 'element-plus/es/components/message-box/style/css'
import 'element-plus/es/components/loading/style/css'
```

后续如果新增其它命令式组件（如 `ElNotification`、`ElMessageBox.confirm` 之外的 Dialog 方法），记得同样补一行样式。

**体积对比**

| | 优化前 | 优化后 |
| --- | --- | --- |
| element-plus 整包 chunk | 922.84 kB（gzip 298.44 kB） | **已消失** |
| 主入口 chunk | — | 196.18 kB（gzip 71.97 kB） |
| 独立 vendor chunk | — | 104.57 kB（gzip 40.74 kB） |
| 组件改为按页面/组件拆分 | — | 如 `el-table-column` 81KB、`el-scrollbar` 46KB 等，只在用到时才加载 |

**验证**：`npm run build` 通过；构建产物 CSS 中确认包含 `el-input__wrapper`、`el-button`、`el-dialog`、`el-table`、`el-switch`、`el-checkbox`、`el-progress`、`el-message`、`el-message-box`、`el-loading-mask` 等样式。

### 2. 长列表渲染优化

**做法**：不是引入虚拟列表，而是用 CSS 的 `content-visibility: auto` + `contain-intrinsic-size`，让浏览器跳过屏外条目的**布局与绘制**。

```css
/* InspireDetail.vue 评论区 */
.comment-root {
  content-visibility: auto;
  contain-intrinsic-size: auto 130px;
}

/* Personal.vue 灵感卡片列表 */
.card {
  content-visibility: auto;
  contain-intrinsic-size: auto 150px;
}
```

**为什么不用虚拟列表**：评论是**变高元素**（正文长短、回复折叠/展开都会改变高度），固定行高的虚拟滚动套不上；自研「测量 + 偏移缓存」的变高虚拟列表工作量和回归风险都不小。`content-visibility` 对变高列表天然兼容，且不改任何业务逻辑与 DOM 结构。

**效果**：200+ 条评论 / 500 条灵感时，屏外条目不再参与渲染与布局，滚动明显更稳。`contain-intrinsic-size` 提供占位高度，避免滚动条跳动。

**后续可选**：如果个人页卡片高度统一，可以换成 `@vueuse/core` 的 `useVirtualList`（项目里已经装了 `@vueuse/core`），做到真正的「只渲染可视区」。

### 3. 图片走缩略图

**新增工具**：`src/utils/media.js`

```js
thumbOf(url, width = 400)
```

两种来源分别处理：

1. **本站上传图**（`/uploads/xxx.jpg`）→ 换成上传时已经生成好的 `thumb_xxx.jpg`（400px），**不额外产生任何服务端开销**
2. **图片 CDN**（`img.20sherry.com`）→ 追加 `?w=400`，交给 Nginx 的 `image_filter` 模块动态缩放 + 转 WebP
3. 其它图源（picsum 等）保持原样

**已应用**：`Search.vue` 的搜索结果卡片图片。

**效果边界（重要）**：目前前台的图片上传走的是 `/file/upload`（存本地磁盘 `/uploads`），**并没有走 MinIO + img CDN**；种子数据的配图是 picsum 外链。所以：

- `/uploads` 的图能立刻用上 `thumb_` 缩略图 ✅
- `?w=` 这条要等图片真正走 `img.20sherry.com` 才会生效

如果希望列表图片全面受益，下一步可以把上传链路切到 MinIO + img 域名（后端 `ImageUploadServiceImpl` 已经实现了这条链路，只是前台没走）。

### 4. qrcode 懒加载

`InspireDetail.vue` 里从顶层 `import QRCode from 'qrcode'` 改成在生成海报时动态加载：

```js
const { default: QRCode } = await import('qrcode')
const qrDataUrl = await QRCode.toDataURL(shareUrl, { ... })
```

详情页首包不再包含二维码库，只有点「生成分享海报」时才去拉这个小 chunk。

### 5. GET 请求缓存 + 并发去重

`src/utils/request.js` 新增：

```js
export function cachedGet(url, params, ttl = 5 * 60 * 1000)  // 5 分钟内存缓存 + 并发去重
export function clearGetCache()                              // 立即失效
```

- 5 分钟内重复请求直接命中内存，切页面零等待
- 同一时刻的并发请求只发一次，其余复用同一个 Promise（避免首页同时挂载多个组件时重复打同一个接口）

**已接入**：`getCategoryTree()`（分类）、`getWordCloud()`（词云）—— 这两个是公开数据、基本不变、又在多个页面被请求。

**缓存失效**：后台「分类管理」「词云管理」在保存/删除成功后会调用 `clearGetCache()`，所以后台改完前台立刻生效，不会卡 5 分钟。

## 五、后续可继续做的

### 5.1 路由级懒加载进度条（已完成）

`router/index.js` 接入 `nprogress`：

```js
NProgress.configure({ showSpinner: false, trickleSpeed: 120, minimum: 0.12 })
router.beforeEach(to => NProgress.start())
router.afterEach(() => NProgress.done())
router.onError(() => NProgress.done())   // chunk 拉取失败也要收掉，避免卡在加载态
```

配色在 `App.vue` 的全局样式里改成站点主色薄荷绿 `#4f8a48`，进度条高度 3px。

### 5.2 图片 srcset + 响应式尺寸（已完成）

`utils/media.js` 新增 `srcsetOf(url)`：只有「缩略图与原图确实不同」时才返回 srcset，避免无意义的多余请求。

```html
<img
  :src="thumbOf(item.img)"
  :srcset="srcsetOf(item.img)"
  sizes="(max-width: 640px) 45vw, 300px"
  loading="lazy"
  decoding="async"
/>
```

已应用到搜索结果卡片。移动端会挑 400w 的缩略图，桌面高 DPR 屏才会拉原图。

### 5.3 登录态并发刷新修复（已完成，附带产出）

排查「明明登录了却被踢回登录页」时发现的真 bug：请求拦截器里，当已有刷新在飞时，**并发请求会裸发无 token 的请求** → 网关判「未携带登录令牌」(401001) → 前端清空登录态并跳登录。

修复：并发时挂起等待刷新结果（复用 `pendingQueue`），刷新成功统一带新 token；只有刷新真的失败才按未登录处理。刷新超时同时从 5s 提到 8s。

### 5.4 个人页虚拟列表（未做，有前置阻塞）

技术上 `@vueuse/core` 的 `useVirtualList` **要求一个自身可滚动的容器**，而个人页现在是整页滚动（window scroll）。要上虚拟列表必须：

1. 把「我的发布」列表包进一个固定高度的内层滚动容器（或把卡片改成等高 + 固定行高）
2. 卡片标题目前可换行，需要改成单行省略，否则固定行高会裁切内容

第 1 条会**改变个人页的滚动方式**（变成列表内滚动 + 页面双滚动条），属于交互层面的变更。目前用的是 `content-visibility: auto`，已经能跳过屏外条目的渲染与布局，500 条实测可接受，所以这条不动。

### 5.5 演示图改为生成进 MinIO + 本站取图（已完成）

**背景**：原来演示数据的配图是 `https://picsum.photos/seed/inspire{ID}/800/600` 外链，用户上传的图落在本地磁盘 `/uploads`，**MinIO 从来没被用过**（桶是空的）。外链导致两个问题：依赖外部网络、以及反复出现的 CORS 问题（跨域画 canvas 失败）。

**改法**（按「自包含 + 不依赖 img 域名」的方案）：

1. **演示图由代码本地生成**：`DemoDataSeeder.buildPlaceholderJpeg()` 用 Java2D 画渐变 + 斜纹 + 编号，不依赖任何外部图源。
2. **上传进 MinIO**：固定生成 60 张，灵感按 ID 轮询复用（避免往 MinIO 灌两千张图），写完日志 `演示图就绪 60 张`。
3. **本站取图接口**：新增 `MinioImageController`，`GET /api/file/view?key=upload/demo/0.jpg&w=400`
   - 挂在已有的 `/api/file/**` 路由下，**不新增网关路由**
   - 已加入网关白名单，游客可访问
   - `?w=` 用项目里已有的 thumbnailator 现算缩略图，响应带 `Access-Control-Allow-Origin: *`
   - 只允许 `upload/` 前缀、拦截 `..`，防止路径穿越
4. **不依赖 img.20sherry.com**：那个域名走 Cloudflare Tunnel + 本地 Nginx，实测当时是 502，链路一断图片整体挂掉；本站取图本地/线上行为一致。
5. **`reset-data.sh` 补上种子开关**：以前只重建桶，不会生成数据；现在会 `export INSPIRE_DEMO_SEED=true`，一条命令清空并重建全部数据（含 MinIO 图片）。
6. **`media.js` 支持 ?w=**：识别 `/file/view` 地址并追加宽度参数，列表用缩略图、详情用原图。

**踩到的坑**：`application.yml` 里 MinIO 默认端点是 `http://localhost:9000`，而 MinIO 是独立容器，核心服务连不上（日志报 `Failed to connect to localhost/[::1]:9000`）。已在 docker-compose 的公共环境变量里注入：

```yaml
INSPIRE_MINIO_ENDPOINT: http://minio:9000
INSPIRE_MINIO_ACCESS_KEY: ${MINIO_ROOT_USER:-minioadmin}
INSPIRE_MINIO_SECRET_KEY: ${MINIO_ROOT_PASSWORD:?MINIO_ROOT_PASSWORD is required}
INSPIRE_MINIO_BUCKET: inspire-img
```

**实测结果**

```
种子日志：演示图就绪 60 张（已存入 MinIO）
MinIO 对象数：60

GET /api/file/view?key=upload/demo/0.jpg        → 200  image/jpeg  25445 字节  ACAO: *
GET /api/file/view?key=upload/demo/0.jpg&w=400  → 200              13439 字节（缩略图生效）
GET /api/file/view?key=upload/../../etc/passwd  → 400（路径穿越被拒）
```

**注意**：已生成的库不会再重新灌数据（种子按「该用户已有灵感就跳过」幂等）。要让演示图换成 MinIO 版本，需要跑一次 `./reset-data.sh`（会删除全部数据卷并重新生成）。历史用户图存在 `/uploads` 且路径已写进数据库，**重置不影响它们**。
