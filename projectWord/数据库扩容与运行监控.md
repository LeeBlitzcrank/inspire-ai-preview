# 数据库扩容与运行监控

> 更新时间：2026-09-24
> 对应迁移：V4 关注流收件箱、V5 计数投影与归档表

## 一、当前新增结构

### user_feed

关注流由原来的：

```sql
user_id IN (关注列表)
```

改为收件箱模型：

```text
发布灵感
→ 按关注者扇出 user_feed
→ 用户直接读取自己的 user_feed
```

表按 `user_id` HASH 分区 32 个分区：

```sql
PRIMARY KEY (user_id, id)
KEY idx_user_time (user_id, create_time, id)
```

优点：

- 读取不再依赖不断增长的 `IN` 列表。
- 关注流可以按用户分区裁剪。
- 取关时可以删除该关注者对应的收件箱内容。
- 新关注时回填最近 100 条内容，避免关注后空窗。

### inspire_metric

新增独立计数投影表：

```text
inspire_id
view_count
like_count
collect_count
comment_count
share_count
heat
```

应用启动 30 秒后先做一次全量对账，之后每 10 分钟只对最近 15 分钟变化的灵感和尚未投影的灵感做增量对账。

当前 `inspire_main` 仍保留计数字段，作为过渡期兼容字段。后续切换读流量时，应按以下顺序推进：

1. 所有读接口改为读取 `inspire_metric`。
2. 点赞、收藏、评论、浏览写入改成事件驱动更新投影。
3. 对账任务只负责修复偏差，不再承担主写入。
4. 确认无回归后再逐步停止业务对 `inspire_main` 计数字段的直接更新。

### 归档表

新增：

```text
message_archive
user_notification_archive
web_vital_metric_archive
ai_call_log_archive
user_ai_history_archive
```

归档任务每天凌晨 3 点执行，默认保留 180 天，每次每张表最多处理 500 条。

流程：

```text
读取过期 ID
→ INSERT IGNORE 到 archive 表
→ 删除源表对应 ID
```

归档任务使用 `INSERT IGNORE`，即使上一次复制成功但删除失败，下一次仍可安全重试。

## 二、32 分区容量评估

当前 32 分区适用于单 MySQL 实例的中等规模阶段。

建议容量红线：

| 指标 | 建议上限 | 超过后的动作 |
| --- | --- | --- |
| 单分区互动表行数 | 500 万 | 评估扩到 64/128 分区 |
| 单 MySQL 实例总数据 | 500 GB | 准备归档与冷热分离 |
| 每秒互动写入 | 3000 | 热点计数改为事件聚合 |
| 单表最大索引 | 50 GB | 检查索引并拆分大表 |
| 慢查询 P95 | 200 ms | 立即分析执行计划 |
| MySQL 连接使用率 | 70% | 调整连接池或读写分离 |

注意：MySQL HASH 分区不能在线通过简单命令改成更多分区。扩到 64/128 分区时需要使用新表、双写或停机迁移。

## 三、扩容路线

1. 当前阶段：单 MySQL + 32 HASH 分区 + Redis 浏览计数 + 收件箱流。
2. 单实例压力明显上升：
   - 使用现有归档任务降低冷数据量。
   - 将读请求迁移到从库。
   - 浏览、点赞、收藏计数完全切到 `inspire_metric`。
3. 单表继续增长：
   - 评估 64/128 分区。
   - 消息和通知按时间归档。
4. 写入成为瓶颈：
   - 引入 Outbox，计数更新通过 MQ 聚合。
   - 热点灵感浏览量使用 Redis 分片计数。
5. 单实例无法承载：
   - 迁移到 TiDB、Vitess 或其他分布式 MySQL。
   - 保留现有业务 ID 和逻辑分区键。

## 四、慢查询监控

MySQL 容器已开启：

```text
slow_query_log=ON
long_query_time=0.5
slow_query_log_file=/var/log/mysql/slow.log
```

宿主机文件：

```text
log/mysql/slow.log
```

建议每天检查：

```bash
tail -100 log/mysql/slow.log
```

重点观察：

- `Rows_examined` 远大于 `Rows_sent` 的查询。
- 关注流、评论预览、收藏夹列表的排序查询。
- 没有命中分区裁剪的 `user_feed`、`user_like`、`collect` 查询。
- 对 `inspire_comment` 按非 `inspire_id` 开头条件查询。

## 五、运行检查 SQL

分区数量：

```sql
SELECT TABLE_NAME, COUNT(*)
FROM information_schema.PARTITIONS
WHERE TABLE_SCHEMA = DATABASE()
  AND PARTITION_NAME IS NOT NULL
GROUP BY TABLE_NAME;
```

投影偏差：

```sql
SELECT COUNT(*) AS metric_rows
FROM inspire_metric;

SELECT COUNT(*) AS source_rows
FROM inspire_main
WHERE deleted = 0;
```

关注流收件箱：

```sql
SELECT user_id, COUNT(*) AS feed_rows
FROM user_feed
GROUP BY user_id
ORDER BY feed_rows DESC;
```

归档积压：

```sql
SELECT COUNT(*) FROM message WHERE create_time < NOW() - INTERVAL 180 DAY;
SELECT COUNT(*) FROM user_notification WHERE create_time < NOW() - INTERVAL 180 DAY;
```
