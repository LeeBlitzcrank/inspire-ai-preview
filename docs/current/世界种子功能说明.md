# 世界种子功能说明

> 更新时间：2026-09-29

## 1. 功能定位

世界种子从公版古诗、短篇故事或神话段落出发。原文负责建立人物、场景和情感前提，用户改变一个条件后，系统生成一条新的平行世界线。

当前入口：

```text
前端：/#/world
首页顶部：书本图标
公开预览：docs/current/preview/parallel-story-preview.html
```

AI 推演内容始终与原文分开表达，页面明确标记为“平行创作”，不把生成内容冒充原著或真实历史。

## 2. 当前核心能力

```text
世界种子、世界线、用户分支三层模型
异步生成任务和任务进度
幂等提交，重复点击不会重复生成
章节游标分页
公开列表、详情和章节 Redis 版本缓存
投票独立计数表
```

当前初始种子：

| 字段 | 内容 |
| --- | --- |
| 原文 | 《西游记·第一回》 |
| 作者 | 吴承恩 |
| 世界名 | 水帘洞没有成为王座 |
| 初始背景 | 888 个非空白字符 |
| 主题世界线 | 5 条 |
| 初始分支 | 每条主题线 1 条公共原线 |
| 核心问题 | 如果瀑布消失，花果山还需要一个王吗 |

## 3. 数据模型

迁移文件：

```text
backend/inspire-core/src/main/resources/db/migration/V7__world_seed.sql
backend/inspire-core/src/main/resources/db/migration/V8__world_async_branch_metrics.sql
```

### 3.1 `world_seed`

保存原文锚点和世界级设定。

### 3.2 `world_line`

保存主题世界线，例如“停在洞口”“镜中未来”“不争王位”。

主题世界线不直接承载章节，章节统一挂到具体分支上。

### 3.3 `world_branch`

保存用户真正阅读和续写的分支。

关键字段：

```text
id
seed_id
line_id
owner_user_id
parent_branch_id
title
branch_type
visibility
status
```

分支类型：

```text
CANON：系统公共原线
USER：用户从主题线或公共分支分叉出来的版本
```

当用户选择一个公共分支并生成章节时，系统不会把公共分支改乱，而是创建一条新的用户分支。后续继续生成时复用该用户分支。

### 3.4 `world_chapter`

保存分支章节。

关键约束：

```text
UNIQUE(branch_id, chapter_no)
```

章节按 `branch_id + chapter_no` 唯一，避免不同用户分支之间互相抢占章节号。

### 3.5 `world_vote`

保存用户对某个分支下一章方向的选择。

关键约束：

```text
UNIQUE(branch_id, user_id)
```

### 3.6 `world_branch_metric`

保存预计算计数：

```text
chapter_count
vote_continue
vote_change
vote_question
vote_custom
vote_total
```

世界详情不再实时聚合整张 `world_vote`，投票时事务内同步更新计数表，读请求只读计数。

### 3.7 `world_generation_task`

保存异步生成任务。

关键字段：

```text
task_type
status
user_id
seed_id
line_id
branch_id
idempotency_key
progress
request_json
result_json
error_message
```

关键约束：

```text
UNIQUE(user_id, task_type, idempotency_key)
```

状态：

```text
PENDING
RUNNING
SUCCESS
FAILED
```

## 4. 接口

网关路由：

```text
/api/world/** -> inspire-ai
```

公开接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/world/public/seeds` | 世界种子列表 |
| GET | `/api/world/public/seeds/{seedId}` | 世界、主题线和分支摘要 |
| GET | `/api/world/public/branches/{branchId}/chapters` | 分支章节游标分页 |

登录接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/world/generate` | 提交世界种子生成任务 |
| POST | `/api/world/chapter` | 提交下一章生成任务 |
| GET | `/api/world/tasks/{taskId}` | 查询任务状态和结果 |
| POST | `/api/world/vote` | 对分支提交选择 |

响应中的世界、主题线、分支和章节 ID 全部使用字符串，避免超过 JavaScript 安全整数范围后发生精度丢失。

## 5. 异步任务流程

### 5.1 提交世界种子

```text
校验登录和请求参数
-> 创建 PENDING 任务
-> 立即返回 taskId
-> worldGenerationExecutor 后台执行
-> 调用模型并校验长度
-> 写入 world_seed、world_line、world_branch
-> 任务状态改为 SUCCESS
```

### 5.2 提交下一章

```text
校验登录、主题线和分支
-> 创建 PENDING 任务
-> 立即返回 taskId
-> 后台锁定分支并读取最近章节
-> 调用模型并校验 800 到 1000 字
-> 写入 world_chapter
-> 更新 world_branch_metric.chapter_count
-> 任务状态改为 SUCCESS
```

前端每 1.2 秒轮询任务状态，并展示进度。

## 6. 幂等策略

前端每次点击生成都会发送 `Idempotency-Key`。

后端唯一键：

```text
user_id + task_type + idempotency_key
```

相同用户、相同任务类型和相同幂等键只会返回原任务，不会重复调用模型，也不会重复写入章节或分支。

如果调用方没有传幂等键，后端会根据请求 JSON 生成 SHA-256 摘要。

## 7. 分支规则

1. 每个主题世界线初始化时自动创建一条 `CANON` 公共原线。
2. 用户从公共原线生成章节时，会创建自己的 `USER` 分支。
3. 用户后续在同一个分支继续生成时，追加到该用户分支。
4. 用户不能覆盖公共原线或其他人的分支。
5. `parent_branch_id` 保留分叉来源，便于后续显示引用链。

## 8. 章节分页

接口：

```text
GET /api/world/public/branches/{branchId}/chapters
    ?beforeChapterNo=20
    &size=10
```

查询规则：

```text
chapter_no < beforeChapterNo
ORDER BY chapter_no DESC
LIMIT size + 1
```

返回 `items / nextBeforeChapterNo / hasMore`。前端会把当前页反转成从早到晚的顺序，并在用户点击“加载更早章节”时向列表头部插入旧章节。

## 9. 缓存设计

缓存使用 Redis，但采用版本号失效，不扫描 `world:*` 键：

```text
world:cache:version
world:cache:v{version}:public:seeds
world:cache:v{version}:public:seed:{seedId}
world:cache:v{version}:branch:chapters:{branchId}:{before}:{size}
```

生成成功或投票成功后递增版本号，旧缓存自然过期，避免 `KEYS` 扫描。

## 10. 查询性能

世界列表：

```text
1 次主查询，同时返回主题线数量
```

世界详情：

```text
1 次查询世界主体
1 次查询全部主题线
1 次批量查询所有分支和计数
1 次窗口查询每个分支最新章节
```

不再按世界种子逐条执行 `COUNT(*)`，也不再按世界线逐条查询章节和投票。

## 11. 长度约束

初始世界背景和下一章正文都要求：

```text
800 <= 非空白字符数 <= 1000
```

实现方式：

1. 首次模型提示词要求目标 850 到 950 字。
2. 不合格时使用纯文本编辑提示词重写，最多 3 次。
3. 最终仅偏长时按完整句子边界截断到 1000 字以内。
4. 少于 800 字时任务失败，不写入数据库。

## 12. 事务与并发

```text
生成世界种子：world_seed / world_line / world_branch / metric 同一事务
生成章节：锁定用户分支后计算 chapter_no 并写入章节和计数
投票：锁定分支和用户原投票后更新 world_vote / world_branch_metric
```

应用重启后，`PENDING` 任务以及超过 5 分钟未更新的 `RUNNING` 任务会重新进入执行队列。

## 14. 后续扩展

1. 将后台线程池升级为 MQ 消费，支持多实例公平调度。
2. 增加任务取消、失败重试次数和人工重跑。
3. 为世界搜索、向量检索和分支推荐建立独立读模型。
4. 增加分支点赞、收藏、关注和引用链页面。
5. 对高质量公共分支增加审核和运营精选。
6. 当章节达到千万级后，按 `branch_id` 或时间归档历史章节。
