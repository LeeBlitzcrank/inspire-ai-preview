> 更新时间：2026-09-29
> 范围：前端长列表、世界长章节懒加载、Playwright 测试、Prometheus/Grafana、镜像发布流水线

## 1. 前端虚拟列表

### 1.1 当前实现

个人页“我的发布”已经使用窗口虚拟列表：

```text
固定条目高度：86px
可视区高度：340px
上下缓冲：各 4 条
滚动优化：requestAnimationFrame 量化 scrollTop
分页策略：每批 20 条，接近底部自动加载下一批
```

页面只渲染可视区域和缓冲区的卡片，不再为已加载的几百条数据创建完整 DOM。

关键文件：

```text
frontend/src/pages/personal/composables/usePersonalContent.js
frontend/src/pages/Personal.vue
frontend/src/pages/personal/styles/personal.css
```

### 1.2 使用边界

虚拟列表适合：

```text
条目高度稳定
单个列表可以持续加载几十到几百条
卡片内部没有跨条目布局依赖
```

暂不自动虚拟化：

```text
瀑布流变高卡片
评论区折叠楼层
后台 Element Plus 表格
```

这些场景需要动态高度测量或独立虚拟表格方案，不能直接套固定高度窗口。

## 2. 世界长章节懒加载

世界种子详情已经使用后端游标分页：

```text
GET /api/world/public/branches/{branchId}/chapters
    ?beforeChapterNo=20
    &size=10
```

前端同时做了正文懒渲染：

```text
默认只展开最新章节
历史章节只显示章节号、字数、标题和展开按钮
用户点击后才渲染正文段落
加载更早章节后继续保持当前展开状态
```

关键文件：

```text
frontend/src/pages/world/composables/useWorldSeed.js
frontend/src/pages/WorldSeed.vue
frontend/src/pages/world/styles/world.css
```

这样即使一条世界线累计几十章，首屏也不会一次渲染全部长文本。

## 4. Prometheus + Grafana

监控服务使用 Docker Compose 的 `monitoring` profile，默认不随普通启动命令启动。

### 4.1 启动

```bash
bash scripts/monitoring-up.sh
```

等价命令：

```bash
docker compose --env-file .env --profile monitoring up -d prometheus grafana
```

访问地址：

```text
Prometheus: http://127.0.0.1:9090
Grafana:    http://127.0.0.1:3000
```

默认账号：

```text
admin / admin
```

生产环境必须通过环境变量修改：

```text
GRAFANA_ADMIN_USER
GRAFANA_ADMIN_PASSWORD
```

### 4.2 采集服务

```text
inspire-gateway:8080
inspire-auth:8081
inspire-ai:8082
inspire-core:8083
inspire-admin:8085
inspire-search:8086
inspire-rag:8087
```

采集路径：

```text
/actuator/prometheus
```

### 4.3 默认仪表盘

自动导入：

包含：

## 5. 后端镜像发布流程

### 5.1 本机构建

只构建，不推送：

```bash
bash scripts/build-release-images.sh
```

指定标签：

```bash
IMAGE_TAG=v1.0.0 bash scripts/build-release-images.sh
```

构建并推送：

```bash
IMAGE_REGISTRY=registry.example.com/inspire \
IMAGE_TAG=v1.0.0 \
PUSH_IMAGES=1 \
bash scripts/build-release-images.sh
```

脚本会：

```text
先构建所有后端 JAR
再逐个构建 Docker 镜像
按统一版本标签标记
可选推送到 Registry
```

### 5.2 GitHub Actions

工作流：

```text
.github/workflows/publish-images.yml
```

触发方式：

```text
推送 v* Git Tag
手动 workflow_dispatch
```

推送目标：

```text
ghcr.io/<owner>/inspire-auth:<tag>
ghcr.io/<owner>/inspire-ai:<tag>
ghcr.io/<owner>/inspire-core:<tag>
ghcr.io/<owner>/inspire-admin:<tag>
ghcr.io/<owner>/inspire-search:<tag>
ghcr.io/<owner>/inspire-gateway:<tag>
ghcr.io/<owner>/inspire-rag:<tag>
```

发布完成后，服务器只需拉取固定标签镜像，不再通过 `docker cp` 临时替换 JAR。
