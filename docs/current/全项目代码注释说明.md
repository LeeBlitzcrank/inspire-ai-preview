# 全项目代码注释说明

> 更新时间：2026-09-30
> 覆盖范围：后端、前端、SQL、脚本、Docker、监控、GitHub Actions 和部署配置

## 1. 注释目标

本次全项目注释的目标是：

```text
快速识别每个文件的职责
明确文件所属模块和系统边界
降低接手代码时的阅读成本
解释复杂流程为什么这样设计
```

没有采用“每一行都加注释”的方式。逐行注释会重复代码字面含义，增加维护成本和 Git diff，不能让读者更快理解系统。

## 2. 注释层级

### 2.1 文件级说明

所有可注释源码和配置文件都包含统一文件头：

```text
文件路径
所属模块
主要职责
维护说明
INSPIRE_FILE_HEADER
```

标记用于幂等更新，重复运行脚本不会重复插入注释。

### 2.2 类和方法级说明

以下逻辑保留或增加方法级说明：

```text
事务边界
并发和锁
缓存及失效
异步任务和重试
鉴权、安全校验
数据迁移
复杂算法
跨模块数据组装
```

### 2.3 行内注释

只用于解释不明显的原因、异常兜底、兼容处理和非直觉规则，不解释简单赋值和显而易见判断。

注释格式按语言区分：

```text
Java：Javadoc
Vue / HTML：HTML 注释
JS / CSS：块注释
SQL：-- 注释
Shell / YAML / Dockerfile / conf：井号注释
XML / SVG：XML 注释
```

## 4. 排除文件

以下文件不需要添加业务代码注释：

```text
frontend/node_modules
frontend/dist
backend/**/target
out
.git
backend/**/db/migration
图片、字体、favicon 等二进制资源
package-lock.json
依赖生成的元数据
```

Flyway 已执行迁移文件不能增加或修改注释，否则 checksum 会变化并导致服务拒绝启动。迁移文件结构只通过新增版本维护。

JSON 不支持注释，因此采用合法描述字段代替：

```text
frontend/package.json -> description
MinIO 策略 -> Sid
Grafana Dashboard -> description
```

Postman Collection 和纯生成 JSON 通过主文档说明用途，不强行插入伪注释。

## 5. 批量维护脚本

脚本：

```text
scripts/add-source-file-headers.mjs
```

运行：

```bash
node scripts/add-source-file-headers.mjs
```

脚本特性：

```text
自动识别语言注释格式
自动识别模块、Controller、Service、Mapper、Vue、Composable、SQL、脚本等职责
幂等，不会重复插入
跳过构建产物、依赖目录和二进制文件
修正 shebang、XML 声明和 HTML DOCTYPE 顺序
```

新增源码后可以再次运行，补充缺失文件头。

## 7. 注释维护原则

1. 文件职责变化时同步更新文件头。
2. 事务、锁、缓存、异步和权限逻辑修改时必须更新相关注释。
3. 删除过期注释，不能保留与代码相反的说明。
4. 不在注释中写入真实密码、Token、邮箱授权码或第三方 Key。
5. 不解释显而易见的代码，优先解释设计原因和数据边界。
