# 推荐系统落地说明

> 更新时间：2026-10-09
> 状态：规则个性化、行为反馈、向量召回、多路召回、稳定分桶和 A/B 指标已实现；机器学习排序暂未上线。

## 1. 目标

推荐从“全站热度排序”升级为可解释的个性化推荐：

- 结合分类、作者、热度、新鲜度和负反馈。
- 使用内容向量发现语义相似但标题或分类不同的灵感。
- 异步采集曝光、点击、收藏、跳过和停留行为。
- 使用稳定分桶验证新推荐的收藏率、停留时长和跳过率。

## 2. 推荐链路

```text
前端曝光/点击/收藏/跳过/停留
  -> RocketMQ topic_recommend_event
  -> 推荐事件消费者
  -> MySQL recommend_event
  -> Redis 用户画像与兴趣向量缓存

推荐请求
  -> 稳定 A/B 分桶
  -> 热点召回
  -> 分类召回
  -> 作者召回
  -> 推荐向量召回
  -> Java 规则排序
  -> 分类多样性重排
  -> 推荐理由
```

## 3. 数据库

### recommend_event

记录推荐行为：

```text
user_id
inspire_id
event_type
reason_code
experiment_id
variant
duration_ms
create_time
```

支持的事件：

```text
IMPRESSION
CLICK
DETAIL
COLLECT
LIKE
SKIP
NEGATIVE
DWELL
```

### recommend_vector_state

记录推荐向量索引同步状态，和 `inspire_recommend_vector` 一一对应。

## 4. 推荐向量索引

索引名：

```text
inspire_recommend_vector
```

每篇灵感一条文档：

```text
inspire_id
title
tag
author_id
heat
create_time
update_time
embedding
```

向量文本由标题、分类和正文组成。优先使用 Ollama embedding，失败时自动降级为本地哈希向量，保证索引链路可运行。

内部接口：

```text
POST /rag/admin/recommend-vector/reindex?limit=5000
GET  /rag/admin/recommend-vector/status
Header: X-Rag-Token
```

定时任务会按 `recommend_vector_state` 增量补齐新发布或修改的灵感。

## 5. 用户兴趣向量

用户兴趣向量由最近的正向行为生成：

```text
点赞
收藏
打开详情
点击
停留时间 >= 3 秒
```

系统从推荐向量索引取出对应内容向量，求平均并归一化，Redis 缓存默认 30 分钟。

负反馈包括：

```text
SKIP
NEGATIVE
停留时间 < 1.2 秒
```

负反馈会降低对应分类的分数，最近跳过的内容会从后续候选中排除。

## 6. 多路召回

候选内容由以下来源合并去重：

```text
热点召回
用户偏好分类召回
用户偏好作者召回
内容向量召回
```

热点、分类和作者来自 MySQL；向量召回来自 `inspire_recommend_vector`。

## 7. 排序与重排

当前 Java 规则分数：

```text
finalScore =
  0.30 * 分类兴趣
+ 0.15 * 作者兴趣
+ 0.18 * 热度
+ 0.14 * 新鲜度
+ 0.19 * 向量相似度
+ 0.04 * 探索分
- 0.65 * 负反馈
```

重排规则：

- 同一分类在主流中最多连续出现 2 条。
- 被最近跳过或标记负反馈的内容不再进入候选。
- 推荐结果附带 `recommendReason`、`recommendExperiment` 和 `recommendVariant`。

## 8. A/B 实验

实验 ID：

```text
recommend_v2
```

用户按稳定哈希分桶：

```text
hash(userId + experimentId) % 100
```

默认分组：

```text
CONTROL   ：规则个性化，不启用向量召回
TREATMENT ：规则个性化 + 向量召回 + 语义排序
```

推荐事件会保存实验 ID、分组和停留时长。

指标接口：

```text
GET /inspire/admin/recommend/metrics?days=7
Header: X-User-Role: admin
```

指标包括：

```text
impressions
clicks
collects
skips
dwell_events
avg_dwell_ms
```

## 9. 后台推荐管理

后台新增“推荐管理”页面，支持三个区域：

### 推荐配置

可动态调整：

```text
vector_recall_enabled
treatment_percent
push_max_per_day
```

核心服务对配置做 30 秒本地缓存，后台修改后无需重启服务。

### 人工推送

管理员可以创建、编辑、启用、暂停人工推送：

```text
目标灵感
目标人群：全部用户 / 分类偏好用户 / 最近 7 天新用户
权重
开始时间
结束时间
推送原因
```

人工推送作为额外召回来源参与排序，不会绕过个性化结果。单用户每日曝光次数由 `push_max_per_day` 控制。

### 推送效果

每次推送事件会保存 `push_id`，后台可按推送查看：

```text
曝光
点击
收藏
跳过
平均停留时长
```

后台接口：

```text
GET  /api/admin/recommend/config
PUT  /api/admin/recommend/config
GET  /api/admin/recommend/push
POST /api/admin/recommend/push
PUT  /api/admin/recommend/push/{id}
POST /api/admin/recommend/push/{id}/status
GET  /api/admin/recommend/metrics
```

## 11. 运维

查看推荐向量状态：

```bash
curl -H "X-Rag-Token: $INSPIRE_RAG_ADMIN_TOKEN" \
  http://127.0.0.1:8087/rag/admin/recommend-vector/status
```

重建推荐向量：

```bash
curl -X POST -H "X-Rag-Token: $INSPIRE_RAG_ADMIN_TOKEN" \
  "http://127.0.0.1:8087/rag/admin/recommend-vector/reindex?limit=5000"
```

查看 A/B 指标：

```bash
curl -H "Authorization: Bearer <admin-token>" \
  "http://127.0.0.1:8080/api/inspire/admin/recommend/metrics?days=7"
```

## 12. 后续阶段

当前未上线机器学习排序模型。后续顺序：

1. 使用足够的曝光和收藏样本训练逻辑回归。
2. 离线验证 AUC、NDCG、收藏率和跳过率。
3. 用 shadow mode 对比模型分数，不影响线上排序。
4. 通过 A/B 实验逐步引入 LightGBM 或 ONNX 模型。

大模型只适合生成自然语言推荐解释，不用于高频候选排序。
