# 全局错误弹窗组件说明

## 一、目标

统一所有错误类反馈，避免出现以下问题：

- 同一时间弹出多个错误提示。
- 错误提示一闪而过，用户来不及阅读。
- 点击遮罩、按 Esc 或误触后错误提示自动消失。
- 不同页面使用不同的报错样式和交互方式。

## 二、组件结构

### 1. 弹窗组件

文件：

```txt
frontend/src/components/base/AppErrorDialog.vue
```

职责：

- 渲染全局错误遮罩。
- 在视口中央展示错误标题、错误内容和操作按钮。
- 点击遮罩不关闭。
- 只有点击「关闭」按钮才关闭。
- 文案支持多行。
- 可选的错误详情放在 `pre` 区域展示。

### 2. 单例错误状态

文件：

```txt
frontend/src/utils/errorDialog.js
```

职责：

- 保存当前弹窗状态。
- 控制单例行为。
- 处理重复错误。
- 提供 `showErrorDialog()` 和 `closeErrorDialog()`。

核心约束：

- 弹窗已经打开时，新的错误直接忽略。
- 同一错误在 1.5 秒内重复触发时忽略。
- 错误关闭后，后续新的错误仍可再次弹出。

### 3. 统一反馈入口

文件：

```txt
frontend/src/utils/uiFeedback.js
```

职责：

- `ElMessage.error` → 全局错误弹窗。
- `ElMessage.success` → 继续使用 Element Plus 顶部成功提示。
- `ElMessage.warning` → 继续使用 Element Plus 顶部警告提示。
- `ElMessage.info` → 继续使用 Element Plus 顶部信息提示。

## 三、错误弹窗规则

| 行为 | 规则 |
| --- | --- |
| 同时出现多个错误 | 只展示第一个 |
| 弹窗打开期间发生新错误 | 忽略，不叠加 |
| 相同错误短时间内重复触发 | 1.5 秒内只展示一次 |
| 点击遮罩 | 不关闭 |
| 按 Esc | 不关闭 |
| 自动消失 | 不自动消失 |
| 关闭方式 | 必须点击「关闭」按钮 |
| 展示位置 | 浏览器视口中央 |
| 成功提示 | 保持原顶部轻提示 |
| 警告提示 | 保持原顶部轻提示 |

## 四、全局挂载

`App.vue` 中挂载：

```vue
<AppErrorDialog />
```

组件注册位置：

```txt
frontend/src/components/base/index.js
```

## 五、页面接入方式

页面继续使用原来的调用方式：

```js
ElMessage.error(res.msg || '操作失败')
```

但导入来源改为：

```js
import { ElMessage } from '@/utils/uiFeedback.js'
```

请求层也统一使用：

```txt
frontend/src/utils/request.js
```

因此以下错误都会进入统一个全局弹窗：

- 网络异常。
- 服务端 5xx。
- 登录失效。
- 权限不足。
- 旧密码错误。
- 收藏、评论、上传、视频处理、后台保存等业务错误。

## 六、已验证场景

### 修改密码失败

输入错误旧密码后，页面中央显示：

```txt
操作失败
旧密码不正确
[关闭]
```

弹窗不会自动消失，也不会因为点击遮罩关闭。

### 重复错误

弹窗打开期间再次触发错误，不会继续生成第二个弹窗。

### 成功和警告

登录成功、保存成功、收藏成功等仍使用顶部轻提示，不进入错误弹窗。

## 七、后续扩展规范

新增页面或新增接口时，错误反馈统一遵循：

```js
import { ElMessage } from '@/utils/uiFeedback.js'

ElMessage.error('明确的用户可理解错误')
```

禁止：

- 新增页面直接使用 `ElMessage.error` 的 Element Plus 原始导入。
- 使用 `window.alert()` 处理业务错误。
- 在页面内自行实现多套错误弹窗。
- 错误弹窗叠加、自动关闭或在遮罩点击时关闭。
