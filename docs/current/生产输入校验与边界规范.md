# 生产输入校验与边界规范

> 更新时间：2026-10-08  
> 适用范围：前台用户接口、后台管理接口、AI 接口、世界种子接口、文件与消息接口。

## 1. 设计原则

真实网站的输入校验不能只依赖前端 `maxlength`。用户可以直接调用接口、修改请求体或复用旧客户端，因此本项目采用三层边界：

1. **前端提前提示**：减少无效请求，改善填写体验。
2. **DTO 注解校验**：Controller 接收请求时快速拒绝明显非法数据。
3. **Service 最终校验**：内部调用、消息重放、异步任务恢复也必须经过同一规则。

数据库字段宽度是最后的存储边界，不再承担“用户提示”职责，但必须和业务规则配套，避免合法请求最终变成 500。

## 3. 已修复的后端入口

### 认证

- 注册账号、昵称、邮箱、密码统一归一化后再写库。
- 登录会 trim + 转小写账号，并对密码做最大长度保护。
- 修改密码会在 Service 层重新执行密码策略，不信任前端。
- 密码修改或重置成功后清理旧刷新会话，并让前端重新登录。
- 忘记密码对未注册邮箱静默返回，避免通过报错枚举账号。
- 弱密码历史账号登录后强制先修改密码；开发环境种子账号可通过白名单豁免。

### 短信登录

- 手机号验证码发送有 60 秒冷却、每日次数上限和验证失败次数上限。
- 验证码保存在 Redis，验证成功后立即删除，只能使用一次。
- 未绑定手机号验证成功后自动创建账号，已绑定手机号直接登录。
- 已登录用户可以验证手机号并绑定到当前账号，手机号唯一。
- 生产环境通过 `INSPIRE_SMS_WEBHOOK_URL` 和 `INSPIRE_SMS_WEBHOOK_TOKEN` 接入真实短信供应商。
- 开发环境 `dev-return-code=true`，验证码会回显并自动填入，便于本地和自动化测试。

### AccessToken 即时失效

- JWT 增加 `tokenVersion` 和 `passwordUpgradeRequired` 声明。
- 网关同时校验黑名单和 Redis 当前用户令牌版本。
- 改密、密码重置、管理员踢人时递增版本，旧 AccessToken 立即返回 `401002`。
- 弱密码账号的 AccessToken 只能访问改密、个人信息、刷新和登出等必要接口，其他接口返回 `403002`。

### 内容

- 灵感标题不再静默截断，超长直接返回 400。
- 正文、分类、封面、图片列表和城市在 DTO 与 Service 双层校验。
- 评论内容在 Service 层 trim 并检查 500 字上限。
- 评论和回复分页限制页码与每页条数，避免大分页查询。
- 图片列表校验 JSON 数组结构、数量和 URL 协议。

### 私信

- 发送人、接收人、消息类型和内容长度都有 Service 层校验。
- 图片消息内容必须是受支持的 URL。
- `extraJson` 必须是大小受限的 JSON 对象。
- 原先的 `RuntimeException` 改为 `BusinessException`，错误响应更稳定。

### AI 与世界种子

- AI 探索、生成、选择、发布均限制关键词、标题、正文、分类和城市。
- 世界种子请求在进入异步任务前完成归一化和长度校验。
- 世界章节与投票参数拒绝非正数 ID、空白选择项和超长文本。

### 后台管理

- 管理员登录限制账号、密码和 6 位动态验证码格式。
- 分类名称、图标、排序和状态有注解校验。
- 词云内容、权重、排序和状态有注解校验。
- 配置更新和手动推送在 Controller 层做长度与空值校验。
- 后台所有写操作通过统一审计过滤器写入 `admin_audit_log`，记录管理员、接口、摘要、状态、耗时、IP 和 User-Agent。

## 7. 后续扩展方式

新增字段时按以下顺序处理：

1. 在 `ValidationConstants.java` 增加边界常量。
2. 在 DTO 上增加对应 Jakarta Validation 注解和中文消息。
3. 在 Service 层调用 `InputValidation` 做归一化和最终校验。
4. 检查数据库字段宽度是否需要迁移。
5. 在 `frontend/src/utils/validation.js` 增加相同的提前提示。
6. 增加单元测试或 Playwright API 负向测试。

## 8. 已知边界

- 开发环境默认豁免 `user001,user002,user003` 的历史弱密码升级，避免本地演示账号被锁死；生产环境不要配置该豁免。
- 生产短信必须配置真实 Webhook，不能依赖 `dev-return-code`。
- `Map` 请求体已经替换为专用 DTO；后续新增接口仍应遵守相同流程，禁止重新引入匿名 Map 入参。
